не заменяют обязательные условия.

## Сценарий демонстрации
1. Войти администратором.
2. Добавить регулярный платёж.
3. Получить напоминание в Telegram.
4. Войти пользователем и отметить оплату.
5. Показать просроченный платёж.
6. Исправить фактическую дату оплаты, просрочка исчезает.
7. Показать следующий период с отдельным статусом.

## Критерии приёмки (чек-лист жюри)
- [ ] Запуск по README, без авторизации панель и данные недоступны
- [ ] Пользователь не выполняет действия админа, даже через API
- [ ] Следующий период с отдельным статусом, прошлые сохраняются
- [ ] Напоминание минимум за 3 дня, без дублей, оплаченный период без напоминания
- [ ] Оплату можно отметить и отменить, исправление даты убирает ошибочную просрочку
- [ ] RUB, USD, EUR, итоги по каждой валюте отдельно
- [ ] Всё сохраняется после перезапуска, удалённый платёж не напоминает
- [ ] В репозитории код, инструкция, `.env.example` без секретов, тестовые данные

## Открытые вопросы
- Напоминать ли один раз по платежу, который уже просрочен к моменту добавления.
  Предложение: да, один раз, фиксируем в `reminded_at`.
- Другие периодичности кроме ежемесячной: на усмотрение команды, для приёмки не нужны.
