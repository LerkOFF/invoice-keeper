# Invoice Keeper: память проекта

Сервис напоминаний о регулярных платежах, кейс хакатона Aeza РнД (Middle).
Репозиторий публичный: `LerkOFF/invoice-keeper`. Секреты, токены и пароли в репозиторий не класть.

## Где что читать
- Требования и порядок работ: `docs/PLAN.md` (держать чек-лист актуальным, отмечать `[x]` по ходу).
- Архитектура и правила предметной области: `docs/ARCHITECTURE.md`.
- Запуск для жюри: `README.md`.

## Стек
Python, FastAPI, SQLAlchemy, SQLite в volume, фоновый планировщик в процессе, Telegram Bot API, Docker Compose.

## Незыблемые правила предметной области
- Просрочка вычисляется, не хранится: `unpaid` и сегодня позже срока, либо `paid` и `paid_at` позже срока. Оплата в день срока вовремя.
- Даты периодов считаются от якоря (число месяца из первой даты, обрезка до конца месяца), не цепочкой.
- Напоминания: за 3 дня или меньше, без дублей через `reminded_at`, ставится только после успешной отправки.
- Права проверяются на сервере. Админ только из `.env`, через API его не создать, не изменить, не удалить.
- Валюты RUB, USD, EUR, итоги по каждой отдельно, без конвертации.
- Удаление платежа мягкое, история периодов остаётся.
- Все API под `/api/v1`, Swagger на `/api/v1/docs`, `openapi.yaml` в корне.

## Как работать
- Коммиты на русском, от `lerk <lerk@joulerk.ru>`, без упоминаний ассистента (скилл `git-commits`).
- Перед сдачей любого этапа: тесты, обновлённый `docs/PLAN.md`, README пригоден для запуска с нуля.
- `.env` не коммитить, менять только `.env.example`.
- Дополнительные фичи не заменяют обязательные условия приёмки.

## Состояние
- Обязательная часть и критерии приёмки закрыты (см. статус в `docs/PLAN.md`). Дальше только бонусы и живая проверка с настоящим ботом.
- Проверка перед сдачей: `.venv/bin/pytest`, `python3 scripts/export_openapi.py --check`, `python3 scripts/demo.py` на поднятом `docker compose up`.
- Меняешь API: пересобери `openapi.yaml` (`scripts/export_openapi.py`), иначе упадёт `tests/test_openapi.py`.
- Приложение рассчитано на один процесс (замок напоминаний внутри процесса), не запускать несколько воркеров.
