# Архитектура

## Общая схема

Один сервис в одном контейнере. Всё поднимается одной командой `docker compose up`.

```
Браузер ──► FastAPI (/api/v1, статика панели)
                │
                ├── auth / roles (сессии в БД)
                ├── recurring-payments, payment-occurrences, users, summary
                │
                └── Планировщик (фоновая задача, раз в минуту и при старте)
                        ├── догенерация периодов
                        └── напоминания ──► Telegram Bot API ──► чат
                
SQLite (volume /data), схема создаётся при старте через create_all
```

## Модель данных

- **users**: `id`, `login` (уникален), `password_hash`, `role` (`user`), `created_at`.
  Администратор в таблице не хранится: логин и пароль берутся из `.env`.
- **sessions**: `token_hash`, `user_id` (пусто для админа), `is_admin`, `expires_at`.
- **recurring_payments**: `id`, `name`, `amount_minor` (целое: копейки и центы, в коде свойство `amount` как `Decimal`), `currency` (`RUB`/`USD`/`EUR`),
  `first_due_date`, `period` (`monthly`), `created_at`, `deleted_at`.
- **payment_occurrences**: `id`, `recurring_id`, `due_date`, `status` (`paid`/`unpaid`),
  `paid_at` (date, nullable), `reminded_at` (datetime, nullable).
  Уникальный индекс `(recurring_id, due_date)`.

## Правила предметной области

### Периоды
- Дата периода считается от якоря: число месяца из `first_due_date`, обрезанное до последнего дня месяца.
  31 января, 28 февраля, 31 марта. Цепочкой от предыдущего периода считать нельзя.
- Периоды догенерируются до «сегодня плюс месяц». Следующий период виден сразу, со своим статусом.
- Новый период не стирает прошлые оплаты, просрочка не останавливает следующие периоды.

### Просрочка
Не хранится, а вычисляется:
- `unpaid` и сегодня позже `due_date`;
- или `paid` и `paid_at` позже `due_date`.

Оплата в день срока считается вовремя. Исправление `paid_at` пересчитывает просрочку, `due_date` не меняется.

### Оплата
- Подтверждение без даты ставит сегодняшнюю.
- Отмена оплаты ставит `unpaid` и очищает `paid_at`.

### Напоминания
- Условие: период `unpaid`, платёж не удалён, до срока 3 дня или меньше, `reminded_at` пуст.
- Дедуп: атомарный `UPDATE ... WHERE reminded_at IS NULL`. Поле заполняется только после успешной отправки,
  иначе при сбое Telegram напоминание потеряется.
- Платёж добавлен позже чем за 3 дня до срока: напоминание уходит сразу.
- Сообщение: название, сумма, валюта, дата оплаты.

### Удаление платежа
Мягкое: `deleted_at`. История периодов остаётся, напоминания прекращаются.

### Время
Переменная `APP_TIMEZONE`. «Сегодня» считается в ней, даты хранятся как `date`.

## Роли и права

- **Администратор** (из `.env`): добавляет и удаляет регулярные платежи, создаёт, меняет и удаляет
  обычных пользователей, может всё, что и пользователь. Его учётная запись через панель не управляется.
- **Пользователь**: видит общий список, меняет статус «Оплачено / Не оплачено» и фактическую дату оплаты.
- Ограничения проверяются на сервере (зависимость `require_admin`), а не только скрываются в панели.
- Пользователю в `PATCH /payment-occurrences/{id}` разрешены только `status` и `paid_at`.
- Создание пользователя с логином администратора запрещено.

## Авторизация

- `POST /auth/login` принимает `{login, password}`, возвращает токен и профиль, а также ставит cookie `session`
  (`HttpOnly`, `SameSite=Lax`, `Secure` включается через `COOKIE_SECURE`).
- Токен принимается двумя способами: `Authorization: Bearer <token>` (приоритет) или cookie панели.
- В таблице `sessions` лежит только SHA-256 токена, сам токен нигде не хранится. Срок жизни `SESSION_TTL_HOURS`.
- `POST /auth/logout` удаляет именно текущую сессию, остальные сессии пользователя живут.
- Логин администратора никогда не ищется в таблице `users`, пароль сверяется через `compare_digest`.
  Пользователь с таким же логином в базе админом не станет.
- Просроченная сессия, сессия удалённого пользователя и неизвестный токен дают 401.
- Зависимости: `CurrentPrincipal` (любой вошедший, иначе 401) и `AdminPrincipal` (иначе 403).

## API (префикс `/api/v1`)

Вход и сессия:
- `POST /auth/login`, `GET /auth/me`, `POST /auth/logout`

Регулярные платежи (создание и удаление только админ):
- `GET /recurring-payments`, `POST /recurring-payments`, `DELETE /recurring-payments/{id}`

Периоды:
- `GET /payment-occurrences`, `GET /payment-occurrences/{id}`, `PATCH /payment-occurrences/{id}`

Итоги:
- `GET /payments/summary`: суммы по валютам (всего, оплачено, не оплачено, просрочено)

Пользователи (только админ):
- `GET /users`, `POST /users`, `PATCH /users/{id}`, `DELETE /users/{id}`

Документация:
- `GET /docs` (Swagger), OpenAPI-файл `openapi.yaml` лежит в корне репозитория.
